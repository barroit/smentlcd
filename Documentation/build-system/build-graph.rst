===========
Build Graph
===========

Each daemon or controller entry executable links its command objects, selected
library objects, and required external libraries.

Object Selection
================

``mbuild/compile`` defines three library object lists:

``obj-lib``
	Objects linked into both the daemon and controller.

``obj-lib_daemon``
	Objects linked into the daemon.

``obj-lib_ctl``
	Objects linked into the controller.

``SERVICE`` selects platform-specific daemon and controller objects. Compiler
feature probes select compatibility objects for ``obj-lib``. For example, an
empty ``CC_HAS_REALLOCARRAY`` adds ``build/lib/patch/reallocarray.o``.

Compilation
===========

The ``build/%.o`` rule in ``mbuild/compile`` compiles each C source into the
corresponding object under ``build/``. For example, ``lib/log.c`` produces
``build/lib/log.o``.

``lib/unicode_width.c`` is generated by ``scripts/gen-unicode_width_c.py``
before compilation.

Each object depends on its source, ``include/generated/build.h``,
``include/generated/features.h``, and ``build/.flags.cc``. The compilation rule
passes each prerequisite under ``include/generated/`` to the compiler with
``-include``.

``CFLAGS`` also includes ``-include include/generated/config.h`` for every
source file. Per-option dependencies track configuration changes. See
:ref:`build-system/incremental-build:Configuration Dependencies`.

The daemon and controller ``main/version.o`` objects also depend on
``include/generated/worktree.h``. It defines ``WORKTREE_HEAD`` as the current
commit ID and ``WORKTREE_DIRTY`` as the hash of ``git diff HEAD``, or an empty
string when the worktree matchs ``HEAD``.

Command objects also depend on generated command table or declaration headers.
See :doc:`command-generation`.

Linking
=======

The default target, ``build/smentlcd``, depends on both root entry executables.
Their prerequisites include:

.. code-block:: text

	build/smentlcd
	├── build/daemon/main/entry
	│   ├── build/daemon/main_entry.o
	│   ├── $(cmd-obj-daemon_main)
	│   ├── $(obj-lib)
	│   ├── $(obj-lib_daemon)
	│   ├── build/libusb.a
	│   ├── build/.flags.ld
	│   ├── build/.flags.ld-daemon
	│   └── build/smentlcdd (order-only)
	└── build/ctl/main/entry
	    ├── build/ctl/main_entry.o
	    ├── $(cmd-obj-ctl_main)
	    ├── $(obj-lib)
	    ├── $(obj-lib_ctl)
	    ├── build/libdeflate.a
	    ├── build/.flags.ld
	    └── build/smentlcdctl (order-only)

``mbuild/executable`` links each entry's objects and static archive with
``LDFLAGS``. Daemon entries also use ``DAEMON_LDFLAGS``. The generated command
rules supply the entry object and the command objects in its subtree.

``build/smentlcdd`` and ``build/smentlcdctl`` are symbolic links to the daemon
and controller root entries, respectively.

``build/libusb.a`` and ``build/libdeflate.a`` are hard links to
``libusb/libusb-1.0.a`` and ``libdeflate/build/libdeflate.a``, respectively.
The archives must exist before the build. Run ``scripts/build-libusb.sh`` and
``scripts/build-libdeflate.sh`` to build them.
